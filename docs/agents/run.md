# Running the app

Real keys are not needed to see a change working. `npm run dev:fake` builds the page and serves the real API
over in-process Postgres, with the test fakes for Claude and Eleven Music (`src/testing/dev-fake.ts`).
Open http://localhost:3000 (`PORT` changes it). State is in memory and ends with the process.
`/` is the split screen every visitor lands on; the payer's page alone is `/payer`. A visitor works on the Seeded Ode (the shared ledger and Ode, once made) until they press "Make my own Ode" in the split screen's bar; then the ledger, lyrics, Ode and payments they make are theirs alone (an Own Ode, keyed by the `ode_visitor` cookie), and "Back to the Seeded Ode" forgets it. On the Seeded Ode, payments are per browser, and "Reset demo" clears only your browser's. At most 5 Own Odes start a day (UTC, from the fake clock) across all visitors; the sixth visitor is told and stays on the Seeded Ode. An Own Ode takes 1 to 3 friends, paid through the first accounts of `FRIEND_PAYPAL_ACCOUNTS` in ledger order. Under `dev:fake`, notes that mention "Goa" give two friends (Meera and Dev); any other notes give the seed's three.

- `FAKE_FLAGGED=1 npm run dev:fake`: Claude writes one lyric line with an amount no rewrite fixes, so the page shows a flagged line.
- The page flow: paste any notes, "Build the ledger", "Write the lyrics", pick a "Release date" (required, a month out by default; "Make the Ode" waits until there is one), "Make the Ode", then pay a friend. With no PayPal client ID the page shows a plain "Pay <friend>" button instead of PayPal's popup; the server runs the same create, read-back and capture against a fake PayPal.
- To drive it headless, import `playwright-core` from the bun cache (it is not in `node_modules`) and launch the cached Chromium:
  ```js
  import { chromium } from "/home/srinivas/.bun/install/cache/playwright-core@1.63.0@@@1/index.mjs";
  const browser = await chromium.launch({
    executablePath: `${process.env.HOME}/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome`,
    args: ["--autoplay-policy=no-user-gesture-required"],
  });
  ```
  On a machine without that cache, `npm i playwright-core@1.63.0` in a scratch directory, `npx playwright-core install chromium`, and point `PLAYWRIGHT_CORE=<that dir>/node_modules/playwright-core/index.mjs` at it when running `drive-fake.mjs`. Chromium also needs `libnspr4`, `libnss3` and `libasound2t64`: `sudo apt install` them, or `apt-get download` the three, `dpkg-deb -x` each into a directory and set `LD_LIBRARY_PATH` to its `usr/lib/x86_64-linux-gnu`.
  Building a ledger over an existing one asks `window.confirm`; a fresh `dev:fake` process has none. A second tab needs `browser.newContext()` then `context.newPage()`; `browser.newPage()` forbids `context.newPage()`.
- `node scripts/drive-fake.mjs [shot.png]` runs that whole flow against a running `dev:fake` (`PORT`), opens Tharun's friend link in a second tab (`/f/<token>`, shown under his name on the payer's page) and pays Tharun $50, printing how long his open tab took to show the unlock (that includes the payer's order and capture requests, so 300 to 2400 ms on a loaded machine; the API test measures from the end of the payment), then rebuilds the ledger and checks his tab says the link no longer works. It ends on `/split` (the payer's page in the left iframe as `/?quiet`, a friend picker and that friend's `/f/<token>` view in the right one): it makes a new Ode, pays Tharun $50 on the left, asserts the right pane unlocked and played while the left stayed quiet, clicks through Vikram, Sahiti and Tharun, repays everyone (Sahiti a cent short first) and checks both panes show the chorus locked until the last payment, then "Full Ode dropped · Florida '25", and checks the panes sit side by side wide and stack at 390 px (screenshot `split-<shot.png>`). It then opens `/` in a second browser context (its own cookie) and checks that browser's copy is unpaid with the chorus locked while the first is still repaid with the chorus dropped, that paying in one leaves the other alone and a reload keeps each, that "Reset demo" clears only its own browser's copy, and that clearing the cookie gives a fresh copy. The fake Ode's audio is junk bytes, so nothing is audible; the script records each `play()` request and where it started instead.
- The verse share: once a friend has a line unlocked their page shows "Share my verse", which makes a link `/s/<token>` (no button before). `/s/<token>` is the share's page; its HTML carries the Open Graph and Twitter tags a chat app reads (`curl` it to see them), `/s/<token>/card.png` is the 1200 x 630 preview image, `/api/shares/<token>` the data and `/api/shares/<token>/audio` the clip. `dev:fake` reads `dist/index.html` once at start, so restart it after a `vite build`. `drive-fake.mjs` covers this in its first section: no button at 0 lines, button at 2, a stranger's browser opens the link and sees only those two lines, the page's play (junk audio cannot be decoded, so it falls back to the plain audio element and the `play()` is recorded), then fetches the HTML without script, reads the tags and fetches the image (saved as `card-<shot.png>`).
- The release date: the Ode shows "N of 3 friends · D days to drop" on the payer's page and every friend's view, and "Delayed · N of 3 friends repaid · was due <date>" once the date has passed with a friend unpaid (the chorus stays locked). The fake clock never moves by itself; `POST /dev/clock/advance-days` with `{"days": 11}` (dev-fake only) moves it. `POST /api/ode` without a date is a 422. `drive-fake.mjs` checks the page's field is required (cleared, "Make the Ode" is disabled), picks dates relative to the clock's day (`GET /api/health`), checks the countdown on the payer's page, a friend's tab and both split panes, advances the clock past the date with Sahiti a cent short and checks both panes read delayed with the chorus locked (the friend's open pane within 2.5 s), then that the last payment replaces the line with the drop.
- Own Odes: after the visitor-copy checks, `drive-fake.mjs` opens `/` in a new browser context, presses "Make my own Ode", builds a two-friend Ode from Goa notes, pays Meera $100 and checks the friend pane unlocks within 2.5 s and offers Meera and Dev (not Tharun); that the first browser's Seeded Ode is unchanged; that "Back to the Seeded Ode" returns to Tharun, Vikram and Sahiti; then it starts four more Own Odes through the API (the day's fifth) and checks the next "Make my own Ode" shows the cap message and leaves the visitor on the Seeded Ode (screenshot `own-<shot.png>`).
- The voice label: the Seeded Ode is unlabelled until the one-off conversion runs, then every pane of it (the payer's page, a friend's view, both split panes) reads "in my voice"; an Own Ode never does, and making the Seeded Ode again (building its ledger over) takes the label away with the converted audio. `dev:fake` has `POST /dev/seed-voice`, the same conversion as `npm run seed:voice` with a fake ElevenLabs and ffmpeg (a second call answers 409). `drive-fake.mjs` checks, inside its judges section, that nothing is labelled before it, that an open friend pane shows the label within 2.5 s after it (and the payer's page on reload), that a judge's own Ode has none, and that "Back to the Seeded Ode" returns to a labelled one (screenshot `voice-<shot.png>`). The label's words are one string in `src/server/voice.ts`; the fallback "a voice like mine" is that one-line change.
- Stop it with `kill $(lsof -ti :$PORT)`. A hook blocks `pkill -f` and `pgrep -f`, which match the shell running them.
- `npm test` takes 2 to 7 minutes: run it in the background. Every run writes its failures to `.vitest/last.json`.

### Converting the Seeded Ode into the payer's voice (once, #35)

`npm run seed:voice` converts the hosted Seeded Ode's stored audio and replaces it. It spends ElevenLabs credits (a stem split and a speech-to-speech pass of about 8 s each for a 35 s song), so run it once, after the Seeded Ode is made and its lines are as wanted. It does not run on Render (there is no ffmpeg there): run it on the payer's own machine against the hosted database.

1. Have Node 24 and `ffmpeg` on the PATH (`ffmpeg -version`; `FFMPEG_PATH` names it otherwise).
2. In `.env`: `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID` (the payer's cloned voice).
3. In `.env.seed` (gitignored, read after `.env`, so it wins): `DATABASE_URL=<ode-db's External Database URL from the Render dashboard>?sslmode=require`. The internal URL only resolves inside Render. Do not put this in `.env`, which the local server also reads.
4. `npm run seed:voice`. It prints the database host (never the keys), runs the schema migration (adds the `voice` column if the web service has not booted since), converts, and prints the original and converted length in ms. A non-zero exit means nothing was replaced.

What it refuses, with nothing replaced: no Seeded Ode yet; already converted (a second run would degrade it; to redo, build the Seeded Ode's ledger over and make it again, which also takes the label away); ElevenLabs or ffmpeg failing; the Seeded Ode being made again during the run; and a converted remix whose length is more than 250 ms from the original's. That last check is how the line windows are kept valid: they were found in the original, and nothing re-finds them, so the remix must be as long. Still check by ear afterwards: click each line on the page and hear that it starts on its words. If the vocals have artifacts at the line edges, keep Eleven Music's vocals (do not run it, or make the Seeded Ode again).

Only the Seeded Ode is touched (`owner = 'seeded'`); judges' Own Odes are never converted or labelled. The page's label is "in my voice"; if the voice is not recognised in the H3 test, change that string to "a voice like mine" in `src/server/voice.ts` and redeploy.

The webhook is `POST /api/payments/webhook`; under `dev:fake` it trusts a request whose `paypal-transmission-sig` header is `valid`. After a payment the page shows a green unlock banner, flares the new lines and plays the first of them.

`npm run dev:server` is the real thing and needs `DATABASE_URL`, `ANTHROPIC_API_KEY` and `ELEVENLABS_API_KEY`, plus `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` and `FRIEND_PAYPAL_ACCOUNTS` to pay friends (and `PAYPAL_WEBHOOK_ID` to trust the capture webhook) (see `.env.example`). They live in `.env` at the repo root (gitignored); `dev:server` and `start` load it, and variables already in the shell win. A git worktree has no `.env`.
